# Build your own exact source catalog

Public-source writer and persistence addition on the v0.3.0 development line.
See [Live Lab update scope](../RELEASE-NOTES-LIVE-LAB.md) for publication status.
Rust only, no LLM or network.

Previously the public reader needed an already encoded catalog. `CorpusBuilder`
now writes the same documented format directly from caller-supplied passages.
The existing reader remains the independent consumer of the generated bytes.

```rust
use gel_source::{Address, CorpusBuilder};
let mut builder = CorpusBuilder::new();
builder.push(Address { node: 1, role: 1 }, 1,
    "My notebook", "Lead", "Exact original text.\n").unwrap();
let encoded = builder.finish().unwrap();
let corpus = encoded.load().unwrap();
let passage = corpus.quote(Address { node: 1, role: 1 }).unwrap();
assert_eq!(passage.quote(), "Exact original text.\n");
```

Run the complete synthetic PL/EN demonstration:

```text
cargo run --locked --offline -p gel-source --example source_build
```

Dependencies must already be available for offline builds. The example emits
exact quotations, separate text/catalog byte sizes and a modified-text rejection.
It does not open private files, access the network, write files or execute input.

## Contract

- UTF-8 bytes, newlines and composed/decomposed Unicode remain unchanged.
- Labels: nonblank, no control characters, at most 512 UTF-8 bytes each, matching
  the existing catalog reader's hex-label limit. Passage bytes are not labels.
- Passages: 1..32768 bytes; total text <=64 MiB, catalog <=16 MiB and <=50000
  records. Those are serialized-content limits, **not** total process RSS limits.
- Duplicate node/role addresses are rejected. Entry/title must stay consistent
  within a node. Different nodes with the same normalized title remain ambiguous.
- Rejected pushes leave existing contents untouched. Empty builders cannot finish.
- Order is caller insertion order. No implicit segmentation, concatenation
  separator, accent removal, newline conversion or truncation is performed.
- `catalog_bytes`, `text_bytes` and their pins support a caller-controlled export.
  The new `gel-source` binary adds bounded file import and no-replace publication.

## Use your own document

```sh
cargo run --locked --offline -p gel-source --bin gel-source -- build input.txt new-bank.gelsrc "My notes"
cargo run --locked --offline -p gel-source --bin gel-source -- read new-bank.gelsrc TRUSTED_SHA256_FROM_BUILD "My notes"
```

Replace the pin argument with the 64 hexadecimal digits printed by `build`, retained
separately in a trusted location. Reading occurs in a new process. A changed file
fails rather than silently returning different content. Unknown titles fail too.
Passages are split at most every 32768 UTF-8 bytes without breaking a character;
this is not semantic segmentation. Concatenating the parts without separators
reconstructs the input, including original newlines. Terminal output escapes
control characters; the underlying quote retains the exact bytes.

The GELSRC01 envelope contains an 8-byte magic, two little-endian u64 lengths,
catalog bytes and text bytes. Its 24-byte header is reported separately.
The full-file pin covers the header and both payloads. A pin delivered by an
untrusted sender is not approval of their data. This format is **plaintext**,
not a private knowledge vault. Never use it for data you intend to encrypt.

Publication writes and syncs a new temporary file beside the destination, then
hard-links it to the destination. Existing files, directories and symlinks are
not replaced. Filesystems without hard-link support fail with no fallback.
On Unix, the parent directory is synced; non-Unix directory durability after
power loss is not claimed. An error after linking can leave a complete target;
inspect it instead of deleting it blindly. A killed process can leave its
temporary file. The program does not scan/delete arbitrary temporary files.
This is not a hardware power-cut test. Both input and output parent directories
must be controlled by the caller: portable path checks are not protection against
an attacker racing path replacements. Unix files are created with mode 0600;
other systems use their normal inherited access policy.

`BUILD_MS` measures import, encoding, hashing, publication and sync, excluding
terminal output. `LOAD_LOOKUP_MS` measures reading, integrity checks and title
lookup, excluding printing. Neither metric measures AI generation or ORB/s.

## Trust and scope

Hashes generated from your own input document that input. Hashes supplied by an
untrusted sender do not authenticate that sender or their statements. When loading
external data, pass independently trusted pins to `Corpus::load`.

This is a **source-catalog writer**, not the private ORB printer, Q8 numeric
quantizer, multimedia analyzer, semantic retriever or speaker. Source addresses
are caller declarations, not certified links to an independently verified ORB bank.
It does not prove truth or add fourfold independent capacity.

Tests cover PL/EN and Unicode byte ranges, deterministic serialization, size and
label limits, conflicting records, failed-push atomicity, modified-byte rejection,
stale passages and ambiguous titles. Test counts are correctness checks, not
semantic accuracy or performance results.
